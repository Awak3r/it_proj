# Сохраняемый локальный sandbox владельца

Стенд создан 15 ноября 2026 в WSL на ПК владельца для ручных проверок справочников и ролей. Это **не production**, не публичный staging и не среда настоящего Telegram-входа.

Команды ниже сохраняют операционную ценность. Версии сборки, назначения и данные описывают записанное состояние стенда, не новый health-check. Текущая модель прав без назначений — в [API](API.md), статус релиза и ручных проверок — в [STATUS](STATUS.md). Не пересоздавать `.local/` ради приведения к свежему seed.

## Открыть

На этом же ПК: **http://127.0.0.1:8080**. Вверху интерфейса есть переключатель demo-пользователей:

| Режим | Demo ID | Что открыть |
| --- | --- | --- |
| Root | `1001` | «Управление root →» → «Управление»: группы, предметы, назначения, работы |
| Преподаватель | `2001` | «Я преподаватель» → «Ведомость» / «Мои события» |
| Студенты | `3001`, `3002`, `3003` | «Я студент» → события / «Мои очереди» / ведомость |

Все имена и данные созданы существующим `scripts/seed-demo.py`, не скопированы из production. Исходный набор:

- группы `М8О-201Б-25`, `М8О-202Б-25`;
- предметы: программирование, математический анализ, физика;
- преподаватель `2001` назначен на три предмета **первой группы**;
- по три работы на предмет — всего девять; у второй группы изначально нет назначений/работ;
- три студента первой группы, три стартовые оценки;
- три события с FIFO / asc / random, семь записей в очереди.

Можно безопасно добавлять/редактировать синтетические справочники через UI. Изменения сохраняются в локальной БД; повторный seed не нужен и откажется работать на непустой базе. Не переносить сюда реальные оценки, production snapshot или credentials.

## Изоляция и версии

- App: `127.0.0.1:8080`, PostgreSQL: `127.0.0.1:55432`, отдельная БД `labturn_dev`.
- Нативные процессы в WSL, Docker не используется: локальный Docker Engine отличается от предусмотренного инструкцией Docker Desktop.
- PostgreSQL **16.15** (доступная локальная версия), Go **1.26.5**, Node **22.23.5**. CI продолжает отдельно проверять PostgreSQL 17 / Go 1.24.x.
- `BOT_TOKEN` пуст, `DEV_AUTH=true`, root только `1001`. Этот режим нельзя открывать в интернет/локальную сеть, туннелировать в публичный URL или включать на production.
- Файлы находятся в `.local/sandbox/`, исключённом из Git: `pgdata/`, бинарник `labturn`, `app.env` (права `600`, только локальный DSN), screenshots `role-1001.png`, `role-2001.png`, `role-3001.png`.
- Сборка приложения основана на `13fb72b5759af603a12e14fc80f2264b2b877732`. При изменении кода локальный бинарник/frontend нужно пересобрать.
- Используются **transient user systemd units** без автозапуска. После остановки WSL/перезагрузки их нужно создать снова командами ниже; данные остаются на диске.

## Проверить и остановить

```sh
systemctl --user is-active labturn-sandbox-db labturn-sandbox-app
curl --fail http://127.0.0.1:8080/api/health
curl --fail http://127.0.0.1:8080/api/config
# config должен вернуть {"dev_auth":true}

# Остановить app, затем DB; данные не удаляются:
systemctl --user stop labturn-sandbox-app
systemctl --user stop labturn-sandbox-db
```

## Снова запустить после остановки / перезагрузки

Команды ниже относятся к **текущему checkout владельца** `/home/bogdanoff/study/labturn`. Не переносить их на VPS. Порты должны быть свободны; существующие сервисы нельзя завершать вслепую. Если unit уже активен, повторно создавать его не нужно.

```sh
systemd-run --user --unit=labturn-sandbox-db \
  --description='LabTurn local sandbox PostgreSQL' \
  --property=Type=exec --property=Restart=on-failure --property=KillSignal=SIGINT \
  /usr/lib/postgresql/16/bin/postgres \
  -D /home/bogdanoff/study/labturn/.local/sandbox/pgdata \
  -h 127.0.0.1 -p 55432 -k /home/bogdanoff/study/labturn/.local/sandbox

/usr/lib/postgresql/16/bin/pg_isready -h 127.0.0.1 -p 55432 -U labqueue
# Дождаться accepting connections, только затем запустить app:

systemd-run --user --unit=labturn-sandbox-app \
  --description='LabTurn local sandbox app' \
  --property=Type=exec --property=Restart=on-failure \
  --property=WorkingDirectory=/home/bogdanoff/study/labturn \
  --property=EnvironmentFile=/home/bogdanoff/study/labturn/.local/sandbox/app.env \
  /home/bogdanoff/study/labturn/.local/sandbox/labturn
```

Не печатать `app.env` или полный process environment. Не удалять `pgdata`, не выполнять повторный `initdb` поверх него. Для пустого стенда создавать новую отдельную БД после согласования, а не уничтожать текущую.

## Проверки создания стенда

- TypeScript/Vite build и Go build: exit 0.
- Проверены пустота новой БД и `/api/config` перед seed, затем точные количества сущностей через локальный API.
- В браузере: root видит группы/назначения, преподаватель — редактируемую ведомость, студент — свою очередь. Smoke-проверка только читала UI, данные не изменяла. Начальные неточные селекторы проверки (имя группы с номером и счётчик у «Мои очереди») исправлены; финальные проверки трёх ролей прошли.
- `ss` подтвердил bind app/DB только на loopback; обе user units активны.

Существующий seed-зависимый regression suite **не запускался на этом сохраняемом sandbox**. Для него использовать отдельную временную БД/приложение или CI, как в [матрице приёмки](archive/qa/ACCEPTANCE.md).

После подготовки стенда агент выполнил отдельный **15-этапный data-changing UI-сценарий**: [результаты и записанное состояние](archive/qa/LOCAL-UI-ACCEPTANCE.md). Студенты 3001/3002 теперь в новой QA-группе, у них заполнена тестовая ведомость, созданное QA-событие завершено. Каталог в начале этой инструкции описывает исходный seed, а не неизменяемую фикстуру.

Доступ с телефона/другого ПК намеренно не настроен. Настоящий Telegram WebView и реальные уведомления потребуют отдельного согласованного стенда с настоящей авторизацией — не публикации этого `DEV_AUTH` sandbox.
