# API

`Authorization: tma <Telegram.WebApp.initData>` — для всех защищённых запросов. `X-Dev-User: <id>` работает **только** с серверным DEV_AUTH=true.

- `GET /api/health` — проверка PostgreSQL.
- `GET /api/config` — только флаг режима разработки, секреты не возвращаются.
- `GET /api/state` — согласованный снимок профиля, доступных событий, записей, ведомостей и справочников. Студент видит предметы учебного плана своей группы. Действующий преподаватель/root видит весь каталог, а ведомости, работы и статистику — для связанных пар предмет/группа. `subject_groups` содержит пары `{subject_id,group_id}` (все для преподавателя/root, только своей группы для студента). Поле `assignments` для совместимости всегда содержит пустой массив.
- `GET /api/updates` — SSE с теми же заголовками авторизации. Событие `change` с `data: {}` означает «перечитать /api/state»; первое подключение и восстановление также дают `change`. `unavailable` включает резервный опрос, пока восстанавливается соединение сервера с PostgreSQL. В потоке нет оценок, имён или идентификаторов пользователей.
- `POST /api/export?subject_id=<id>&group_id=<id>` — преподаватель/root отправляет `.xlsx` ведомость в свой личный чат с ботом; JSON `{"ok":true}` возвращается только после подтверждения Telegram. Бот должен быть запущен пользователем и не заблокирован. При неопределённом сетевом результате сначала проверьте чат: повтор может отправить второй файл.
- `POST /api/command` — JSON-команда + уникальный заголовок `Idempotency-Key` (8–128 символов). Повторяйте неопределённо завершившийся запрос с тем же ключом и телом.

Основные команды:

| kind | Поля |
| --- | --- |
| profile | name, group_id (для преподавателя только 0) |
| group | id (0 — создать), name, enabled (true — архивировать) |
| subject | id (0 — создать), name, enabled (true — архивировать), group_ids[] (группы учебного плана) |
| role | user_id, enabled (роль преподавателя) |
| transfer | user_id, group_id; только без активных записей |
| lab | id (0 — создать), subject_id, group_id, number, name, enabled (true — архивировать), weight, required |
| grade | user_id, lab_id, value (2–5 или null), version (0 при отсутствии) |
| event_create | name, subject_id, group_ids[], starts_at (RFC3339), room, description, duration (минуты), strategy |
| event_update | event_id, name, starts_at, room, description, duration |
| event_action | event_id, action: open / close / start / complete / cancel |
| strategy | event_id, strategy: fifo / asc / desc / random |
| join | event_id |
| leave | event_id, id (ID записи, не пользователя) |
| next | event_id |
| skip / finish / remove | event_id, id (ID конкретной записи) |
| move | event_id, id, position (1-based среди ожидающих) |
| shuffle | event_id |

Ошибки: 400 — нарушено правило; 401 — недействительный вход; 403 — нет прав; 409 — дубликат/конфликт версии/ключа. Текст в поле `error`. Успех команды: `{"ok":true}`.

Клиентский JSON-helper ограничивает запрос (включая чтение тела ответа) 15 секундами. При таймауте команды её результат считается неизвестным: повтор того же действия сохраняет `Idempotency-Key` и тело. После подтверждённой команды интерфейс показывает «Обновляем…» и ждёт актуальный снимок не более 15 секунд суммарно, даже при повторных SSE-инвалидациях. Если снимок не получен, сообщает «Изменение сохранено, но данные не обновились», а не «Готово»; фоновое восстановление продолжается. Это не гарантированное серверное время исполнения и не автоматический повтор изменяющей команды.

## Права преподавателя и root

Root выдаёт и отзывает роль преподавателя командой `role`. Любой действующий преподаватель сразу получает доступ к ведомостям, работам, оценкам и экспорту всех связанных пар предмет/группа без персональных назначений преподавателей. Событие можно создать только для групп, которым назначен выбранный предмет. Чтение событий и очередей доступно преподавателю по всем группам; управление приёмом остаётся у владельца события и root. Произвольное перемещение/удаление участников и перемешивание по-прежнему доступны только root.

Выдача ролей, перевод студентов, создание/архивирование групп и предметов и чтение журнала изменений остаются root-only. В интерфейсе управление преподавателями и студентами и журнал изменений показываются только при отдельном входе в режим root. Выбор и смена режима доступны только root (в том числе выход из его студенческого режима). Обычный пользователь автоматически входит в студенческий или преподавательский режим по серверному флагу `teacher`; незаполненный профиль открывается напрямую, без возврата к выбору роли. Изменение прав через SSE закрывает устаревшие формы и автоматически обновляет режим. Клиентский выбор режима не выдаёт новых серверных прав.

Преподавательская роль исключает студенческое участие: `profile` с ненулевым `group_id`, перевод преподавателя в группу и запись преподавателя в любую очередь отклоняются с HTTP 400. Запись на собственное событие запрещена независимо от роли. При назначении преподавателем `group_id` очищается; если есть waiting/called записи, сначала требуется закрыть их. Старые оценки, история и записи не удаляются; из прежней активной очереди можно выйти. Legacy-преподаватель со старым `group_id` в API профиля/пользователей возвращается без группы и исключается из студенческих расчётов и ведомости. Отзыв роли не восстанавливает группу, очищенную назначением; её нужно выбрать отдельно. Root без явного флага `teacher` может оставаться студентом, сохраняя административные права в привилегированном режиме.

Студент просматривает название и состав своей группы в «Моя группа» на основе уже ограниченного `/api/state`; чужие группы/преподаватели в состав не включаются. Профиль показывает текущую группу; самостоятельная смена после выбора по-прежнему запрещена. Все списки «Управления» поддерживают независимые поиск и страницы максимум по 5 записей (без учёта регистра и различия е/ё; несколько слов ищутся совместно по всему доступному списку, не только текущей странице): группы — название/ID/архив; предметы — название/ID/архив/назначенная группа; преподаватели — имя/фамилия/Telegram ID; студенты — имя/фамилия/группа/Telegram ID; изменения — действие/пользователь/дата. Поиск сбрасывает страницу на первую; обновление снимка корректирует страницу при сокращении списка. Журнал ищется среди возвращённых API последних 100 записей, без прежнего клиентского ограничения 20. Поиск не расширяет права: преподаватели/студенты и журнал по-прежнему показываются только в root-режиме, справочники — при прежних правах управления.

Недоступная кнопка записи объясняет причину: закрытая запись, завершённое событие, отсутствие группы или другая группа. Само ожидание root-перемешивания в случайной очереди не запрещает запись студента.

Назначения преподавателей на пары предмет/группа больше не используются. Команда `assignment` отклоняется; старые записи в БД сохраняются для совместимости отката, но не дают и не ограничивают доступ. Отзыв роли немедленно закрывает преподавательские права независимо от старых назначений; доступ студента к своей группе сохраняется.

## Предметы и группы: учебный план

Связь `subject_groups(subject_id,group_id)` определяет, какие предметы изучает группа. Управляет ею только root, в форме создания/редактирования предмета через выбор нескольких групп. Это **не назначение преподавателя**: действующий преподаватель по-прежнему работает со всеми доступными учебными планами.

- При создании предмета `group_ids` обязателен и должен содержать хотя бы одну существующую действующую группу. Повторяющиеся, несуществующие и новые архивные группы отклоняются с HTTP 400. Создание предмета и связей атомарно.
- При редактировании отсутствующий или `null` `group_ids` сохраняет связи (в том числе при переименовании/архивации старым клиентом). Переданный массив заменяет набор целиком; `[]` означает убрать все связи. Уже назначенные архивные группы допускается сохранить.
- Убрать пару нельзя, пока для неё есть неархивная работа или событие в `planned`/`live`. Ответ 400 предлагает сначала архивировать работы и завершить/отменить события. Оценки, работы и история не удаляются.
- Новая группа не получает все предметы автоматически. Предмет без связей остаётся в каталоге root/преподавателей, но недоступен для новых работ/событий, пока группы не выбраны.
- Новые работы и события требуют действующих связанных групп/предметов; для события проверяется каждая группа. Существующие работы, оценки и экспорт также требуют связи, без изменения прежней политики архивов. Ведомость/статистика и формы событий фильтруются по учебному плану, пустая группа показывает объяснение и отключённые действия.
- Действия с неконсистентным событием без групп или с отсутствующей связью блокируются. Для восстановления остаются доступными авторизованное закрытие записи, завершение/отмена события и собственный выход участника. Права владельца события и root не расширяются.
- Переход к ведомости исторического события с удалённой связью/архивным каталогом сообщает о недоступности, а не открывает другой предмет. Открытые формы закрываются при обновлении учебного плана, чтобы не отправить устаревшую пару.

Миграция `0002_subject_groups.sql` один раз восстанавливает связи из существующих работ (включая архивные) и предметов/групп событий. Неиспользуемые пары не добавляются. Данные сохраняются; повторный startup не возвращает намеренно удалённые связи. Изменение схемы добавочное, но старые клиенты при создании предмета должны передавать `group_ids`.

## Веса работ и расчётные подсказки

`lab.weight` — положительный относительный вес не больше `1000000`; принимается JSON-число или десятичная строка, например `"1.25"`. Строка предпочтительна: она сохраняет точность без преобразования через JavaScript Number. `lab.required` — boolean. При создании отсутствие/null параметров даёт `weight=1`, `required=true`; при редактировании отсутствие/null **сохраняет** прежние значения. Для перевода в необязательные нужно явно передать `required:false`.

В `state.labs` возвращаются `weight` (число для совместимости), `weight_text` (точная десятичная строка для форм и повторной отправки), `required`. Не пересчитывайте `weight_text` через float при редактировании. Некорректные, неположительные, слишком большие или непредставимые PostgreSQL numeric веса отклоняются с HTTP 400.

`state.grade_summaries` — массив серверных расчётов в той же транзакции снимка:

```json
{
  "student_id": 3001,
  "subject_id": 1,
  "group_id": 1,
  "average": 3.67,
  "final_hint": null,
  "required_total": 2,
  "required_passed": 1
}
```

Расчёт делается по всем активным работам пары предмет/группа:

- Обязательная с пустой/null оценкой учитывается за 2. Пустая или оценка 2 блокирует итог.
- Обязательная с оценкой 3–5 считается сданной.
- Необязательная с пустой/null оценкой исключается вместе с весом; с оценкой 2–5 участвует, но не блокирует итог.
- Архивные работы исключаются.
- Средний: `sum(вес × учитываемая оценка) / sum(учитываемых весов)`; `average` округлён до двух знаков.
- `final_hint` появляется только при сдаче всех обязательных и положительном знаменателе. Это обычное округление **неокруглённого** среднего до целого (половина вверх), не повторное округление `average`.
- Если нет учитываемых оценок, `average` и `final_hint` равны null. Для пары без активных работ/участников записи нет; клиент показывает «Нет данных».

Границы доступа одинаковы у работ, оценок и подсказок: root видит всё, студент — свою группу, действующий преподаватель — все связанные пары предмет/группа без персональных назначений. Преподаватели не включаются в студенческие расчёты и не получают новые оценки как студенты; старые оценки сохраняются. Подсказка **не является выставленной итоговой оценкой**, не записывается в `grades`, не меняет очередь. До подтверждения сохранения оценки клиент скрывает её средний/итог, чтобы не выдавать устаревший результат.

## Статистика ведомости

`GET /api/state` дополнительно возвращает `grade_statistics` и `lab_statistics`. Сводки доступны только действующим преподавателям и root; студентам и пользователям с отозванной ролью возвращаются пустые массивы, даже для своей группы. Прежний доступ студента к ведомости и индивидуальным `grade_summaries` своей группы не меняется. В студенческом режиме UI скрывает статистику и для привилегированного аккаунта.

Статистика читается в той же repeatable-read транзакции, что оценки и индивидуальные расчёты, и обновляется после сохранения/SSE. Архивные работы и оценки бывших участников группы не участвуют. Состав группы совпадает с ведомостью и экспортом: учитываются пользователи с соответствующим `group_id` без преподавательской роли. Legacy-преподаватели со старой группой не влияют на количество студентов, средние, задолженности и распределения.

`grade_statistics` содержит запись для каждой пары с активными работами:

```json
{"subject_id":1,"group_id":1,"students_count":3,"labs_count":2,"required_labs_count":1,"debtors_count":1,"final_ready_count":2,"average":3.15,"distribution":{"missing":2,"2":1,"3":1,"4":1,"5":1}}
```

- `average` — среднее **точных неокруглённых индивидуальных взвешенных средних**, с равным вкладом каждого студента. Студенты без учитываемых работ исключаются; результат округляется half-up до двух знаков, при отсутствии данных — null. Это не среднее уже показанных двухзначных значений и не объединённое среднее всех ячеек.
- `debtors_count` — студенты, у которых есть обязательная работа без оценки или с `2`. Необязательные работы не создают долг.
- `final_ready_count` — студенты с ненулевым `final_hint` в индивидуальном расчёте. При отсутствии обязательных работ готовность всё равно требует учитываемых оценок.
- `distribution` — реальные сохранённые оценки активных работ; `missing` отдельно считает отсутствующие/null ячейки. Пустая обязательная участвует в среднем за `2`, **но не становится выставленной двойкой в диаграмме**.

`lab_statistics` содержит `lab_id`, `subject_id`, `group_id`, `students_count`, `graded_count`, `passed_count` (оценки 3–5), `missing_count`, `failed_count` (реальные `2`) и `average` (среднее только выставленных оценок, без подстановки двоек). Лабораторная без участников сохраняет запись с нулевыми счётчиками и average=null. Проценты в UI — passed_count/students_count, при нулевом количестве участников показывается 0%.

В интерфейсе: «Ведомость» → «Статистика», диаграммы оценок/сдачи, поиск студентов и фильтры должников/готовности. Пока есть несохранённая или неподтверждённая правка, показатели скрыты до обновления снимка. Новых изменяющих команд и миграций БД нет. Excel-экспорт в этой итерации не меняется: статистические листы и диаграммы в файле — отдельное расширение.

## Изменения и SSE

Все изменяющие действия логируются. Для оценки дополнительная запись `grade_change` содержит старое и новое значения. Отсутствие Telegram-уведомления не отменяет действие в приложении.

SSE передаёт сигналы после commit через PostgreSQL LISTEN/NOTIFY, в том числе между
экземплярами приложения с общей БД/схемой. Отклонённые команды и идемпотентные повторы
не создают сигнал. Сигналы не хранятся для повторной доставки: после переподключения
клиент получает свежий полный снимок с актуальными правами. Поток общий, но данные
остаются ограничены правами GET state. Изменения напрямую через SQL сигнал не создают.

Heartbeat — каждые 15 секунд; поток закрывается через 30 минут для переподключения.
Валидность Telegram-входа проверяется при открытии и heartbeat. Клиент использует
fetch-stream вместо EventSource, чтобы передавать initData в заголовке, а не URL.
Прокси должен пропускать streaming без буферизации; Caddyfile уже настроен.
