# QA-аудит LabTurn — 14 ноября 2026

Найден и исправлен один подтверждённый дефект: сохранённая оценка могла исчезнуть
из интерфейса при задержке фонового запроса. Серверная запись при этом сохранялась.
Теперь после изменения запрашивается свежий снимок, устаревшие ответы игнорируются,
а правка остаётся ожидающей до подтверждения актуального состояния.

## Результаты финального прогона

| Проверка | Результат | Доказательства |
|---|---|---|
| Go + PostgreSQL, race detector | 23 именованные подпроверки прошли; пропусков нет | [Лог](evidence/qa-go-full.txt) |
| Chromium / Playwright | 8 из 8 прошли, включая 3 новых сценария восстановления | [Лог](evidence/qa-ui-full.txt) |
| TypeScript + Vite | Production build успешен | [Лог](evidence/qa02-refresh.txt) |

Проверены отзыв назначения и роли преподавателя, запись в чужую группу,
конкурентные правки одной оценки, десять одновременных повторов с одним ключом,
сохранение идемпотентности после создания нового экземпляра сервера, восстановление
outbox после ошибки доставки. Уведомления проверены HTTP-заглушкой, реальные
сообщения не отправлялись. Новый экземпляр сервера проверяет сохранность состояния
в БД, но не моделирует аварийное завершение ОС между отправкой и фиксацией транзакции.

В браузере проверены задержанный старый снимок, потерянный ответ успешного POST и
ошибка GET после сохранения. Пока подтверждение не получено, завершение приёма
блокируется. Повтор использует прежний ключ и не увеличивает версию оценки повторно.
Существующие сценарии прав, очередей, root-перемешивания и мобильной ширины сохранены.

## Воспроизведение дефекта

[Тест до исправления](evidence/qa01-before.txt) получил успешный POST, но увидел пустую
ячейку вместо «5». [Регрессионный тест](../../web/tests/recovery.spec.ts) контролирует
задержку ответа через Playwright route, затем проверяет следующее сохранение и API.
Описание причины: [BUG-01](BUGS.md).

При подготовке тестов исправлены две ошибки самих тестов: начальный предмет выбирался
по алфавиту, а проверка БД ожидала программирование; точный label-селектор не находил
выбор предмета. Теперь предмет выбирается явно по id через роль combobox.
Промежуточные неуспешные запуски сохранены в [журнале](EXECUTION.csv) и не считаются
отдельными дефектами продукта. Финальный полный прогон выполнен после этих исправлений.

## Границы результата

Проверялся основной Go/PostgreSQL-проект с синтетическими dev-пользователями.
Интеграционные тесты использовали удаляемую схему, браузерные — локальную демо-БД.
Финальные UI-тесты выполнялись на заново собранном Go-сервере и production web bundle.

Реальный Telegram WebView, HTTPS-развёртывание, настоящая доставка ботом и полная
Docker-сборка в этом прогоне не проверялись. Проверка 100 пользователей / 10 событий
подтверждает корректность запросов в данной среде, не гарантирует время отклика.
Это ограниченный аудит основных рисков, не заключение о полной готовности к релизу.

## Повторный запуск

Из backend с доступной PostgreSQL:

```sh
TEST_DATABASE_URL=postgres://labqueue:labqueue@localhost:5432/labqueue?sslmode=disable go test -race -count=1 -v ./...
go vet ./...
go build .
```

Из web, при запущенном dev API и данных scripts/seed-demo.py:

```sh
npm run build
BASE_URL=http://127.0.0.1:8080 CHROMIUM_PATH=/usr/bin/chromium npm test
```

Если используется Chromium, установленный Playwright, CHROMIUM_PATH следует опустить.
Подробности окружения — [DEVELOPMENT.md](../DEVELOPMENT.md), сценарии — [TEST-CASES.md](TEST-CASES.md).
