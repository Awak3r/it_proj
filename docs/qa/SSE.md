# Проверка SSE

Добавлено обновление ведомости, очередей и прав без перезагрузки через GET /api/updates.
После commit команда отправляет PostgreSQL NOTIFY. Отдельное соединение LISTEN на
каждом экземпляре приложения передаёт клиентам сигнал перечитать доступное состояние.
Данные и Telegram initData не передаются в URL или событиях; авторизация — в заголовках.

Клиент объединяет серии сигналов, переподключается с задержкой, обновляется при возврате
во вкладку/Telegram и восстановлении сети. При недоступности SSE работает резервный
опрос раз в 3 секунды. После reconnect всегда читается полный актуальный снимок.
Caddy отключает сжатие потока и передаёт данные без буферизации.

Проверено:

- [Go с PostgreSQL и race detector](evidence/sse-go.txt): 24 именованные подпроверки прошли.
  Проверка SSE использует отдельный экземпляр сервера: сигнал после commit, отсутствие
  сигнала при конфликте/повторе, reconnect, отказ неавторизованному клиенту.
- [Playwright](evidence/sse-ui.txt): 12 из 12 прошли. Два отдельных браузерных контекста:
  изменение оценки в одном отображается в другом без навигации; резервный опрос в этом
  сценарии отключён. Также проверены offline/online, восстановление вкладки,
  недоступность SSE и повтор начальной загрузки после временной ошибки config.
- TypeScript/Vite production build, go vet и go build завершились успешно.
- На свежем Go-сервере одно SSE-соединение выдержало 45 секунд без изменений:
  heartbeat на 15/30/45 секундах, затем изменение пришло по тому же соединению.
  Это проверяет работу за пределами штатного HTTP WriteTimeout 30 секунд и idle LISTEN.

Реальный Telegram WebView и HTTPS-прокси пока не проверены. Browser-only Sites-демо
не подключено к Go/PostgreSQL и не демонстрирует межпользовательское SSE.
Правки SQL вне API не создают NOTIFY автоматически. Подробности протокола — в API.md.
