# QA LabTurn

Базовая версия: `3329c37`. Проверяется Go/PostgreSQL + React, не браузерная Sites-демонстрация.
Методика: [QA Expert](https://github.com/daymade/claude-code-skills/tree/main/qa-expert),
[Webapp Testing](https://github.com/anthropics/skills/tree/main/skills/webapp-testing),
[Verification Before Completion](https://github.com/obra/superpowers/tree/main/skills/verification-before-completion).
Используется существующий Playwright/Go harness. Результаты запусков — в EXECUTION.csv.

## QA-01: задержанный снимок ведомости (высокий риск)

Преподаватель открывает ведомость. Перехватить очередной GET state после получения
ответа сервера, но до доставки браузеру. Сохранить другую оценку реальным POST.
Ожидание: новая оценка остаётся видимой; свежая версия доступна для следующего
редактирования; запоздалый старый GET не откатывает значение. Проверить БД через API.
Автоматизация: `web/tests/recovery.spec.ts`, stale snapshot.

## QA-02: потерянный ответ сохранения (высокий риск)

Применить POST оценки сервером и оборвать доставку ответа. Ожидание: правка остаётся
видимой с ошибкой; завершение приёма заблокировано; повтор использует прежний ключ,
успешно подтверждает сохранение, версия увеличивается ровно один раз.
Автоматизация: `web/tests/recovery.spec.ts`, lost response.

Дополнительный сценарий: POST принят, но GET state возвращает 503. Ячейка сохраняет
введённое значение и статус ожидающей правки до успешного повторного подтверждения;
повтор не увеличивает версию оценки. Автоматизация: failed refresh.

## QA-03: отзыв доступа и подделка идентификаторов (высокий риск)

Сначала подтвердить разрешённую запись преподавателя. Отозвать назначение, повторить
запись с новым ключом: 403, оценка и аудит не меняются. Проверить чужую группу,
отзыв роли и повторное назначение как положительный контроль.
Автоматизация: `backend/integration_test.go`, revoked access.

## QA-04: конкурентные сохранения и повторы (высокий риск)

Одновременно сохранить два разных значения одной версии: один успех и один конфликт,
одна новая версия. Параллельно повторить один запрос с одинаковым ключом: одна запись
аудита и одна версия. Повторить после создания нового server с той же БД.
Автоматизация: `backend/integration_test.go`, concurrent grade.

## QA-05: восстановление уведомлений (средний риск)

Изолированный outbox; HTTP transport-заглушка, без реальных Telegram-сообщений.
Ошибка доставки сохраняет запись, увеличивает attempts и откладывает повтор.
Повтор после нового экземпляра server доставляет один раз; подтверждённая запись
повторно не отправляется. Проверять payload и состояние БД.
Автоматизация: `backend/integration_test.go`, notification recovery.

## QA-06: регрессия

Полные Go tests с race и PostgreSQL, vet, TypeScript/Vite build, Playwright.
Существующие сценарии проверяют очереди, ручное перемешивание root, права студента,
мобильный viewport, независимость оценки от завершения приёма, конкурентные записи.

## Ограничения

Нет проверки настоящего Telegram WebView, реальной доставки ботом, production HTTPS,
тайм-аутов мобильной сети, обещания задержки до 5 секунд или полного security-аудита.
Интеграционные тесты создают и удаляют отдельную схему. UI-тесты требуют dev-сервер
с данными scripts/seed-demo.py. Команды запуска приведены в ../DEVELOPMENT.md.
