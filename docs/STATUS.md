4. Подтвердить уточнение FR-16: UI вычитает прошедшую часть текущего приёма в пределах одной средней длительности. ETA — приблизительная оценка, не обещанное время.
5. Отдельно согласовать и измерить нагрузочную цель 100 пользователей / 10 событий / обновление до 5 секунд. Исторические тесты корректности и единичные SSE timings не являются SLA.

## Ограничения и риски

- Backup на VPS ежедневный, хранение 7 дней; историческая проверка restore выполнена в отдельную БД. **Offsite backup отсутствует**; потеря VPS остаётся риском. Порядок и согласования — в [DEPLOYMENT.md](DEPLOYMENT.md).
- Rollback образа не откатывает схему и данные. Startup применяет историческую `schema.sql` и упорядоченные `backend/migrations/*.sql` под advisory lock; применённые миграции не редактировать. Нужна обратная совместимость с прежним образом.
- App restart кратковременно прерывает запросы/SSE; zero downtime не обещается. При недоступном SSE работает polling раз в 3 секунды; восстановление получает свежий снимок.
- PostgreSQL LISTEN требует отдельного session-level соединения на экземпляр app; transaction pooling не подходит. Прямой SQL вне API не создаёт NOTIFY автоматически.
- Изменяющие команды используют общий advisory lock (упрощение MVP). Рост нагрузки потребует отдельной оценки блокировок.
- Уведомления из transactional outbox — at-least-once, до восьми попыток с задержками; авария между отправкой и commit может дать повтор. Exactly-once не гарантируется.
- `requests`, `audit`, закрытые записи и outbox не очищаются автоматически. Сроки хранения требуют отдельного решения.
- Перевод студента сохраняет старые оценки у прежних работ; автоматического сопоставления/переноса нет. Не выполнять ручные SQL-переносы на production без согласования.
- Excel-экспорт реализован: `.xlsx` с формулами отправляется в личный чат через бота. Фактическая доставка в Telegram требует ручной проверки; локальные проверки транспорта её не заменяют. Типы работ, конструктор формул и диаграммы — последующие этапы; итоговая подсказка не выставляет оценку автоматически.

Для новых проверок использовать [DEVELOPMENT.md](DEVELOPMENT.md), фиксируя фактический SHA, команды, exit status и пропуски. Не запускать сборки/seed/UI-тесты на VPS и не копировать production-секреты или дампы.
